## 최신 상태 — 2026-10-03

야간 공식 기준은 `docs/야간근무_룰북_v2.21.txt`, 평일 주간은 별도 v1.0이다. 서비스 재로딩 버전은 **2.21.16**, 엔진 호출 옵션은 `rules_version="2.20"`을 유지한다. 현재 구현과 운영 인수인계는 `HANDOFF_주간근무.md`, 규칙·구현 위치는 `docs/RULE_INDEX.md`를 먼저 확인한다.

- 통제 A(ID A)의 04시 보안실 대기를 모든 야간 유형·FM/유도리에서 강하게 회피한다(17-1). 금지하지 않으며 기존 하드룰·관리자 목적·당일 밸런스를 우선한다. 불가피한 배정은 특이사항에 표시한다. 관리자대행에게 적용하지 않는다.
- 20시·04시 외 대기/휴게 표시 횟수에 새로운 강한 균형 목표를 추가하지 않는다. 실제 근무·휴게·피로도 계산은 기존 규칙을 따른다.
- PC 야간 이력 가져오기: 현장 양식 Excel(.xlsx/.xlsm) 또는 PNG/JPG → 날짜·모드·표시번호와 실제 직원·배정 확인 → 실제 이력 저장. 이미지 OCR은 Windows 로컬 처리이며 검토 후 저장한다. 하단 메모를 자동으로 업무에 반영하지 않는다. A 결근/관리자대행 표 가져오기는 현재 지원하지 않는다.
- PC·모바일 야간 근무표의 현장 양식 PNG 다운로드를 지원한다. CP·셔틀은 엔진 배정이 없어 빈칸이다. Excel 출력 함수는 유지하지만 현재 다운로드 UI는 현장 이미지 중심이다.
- 야간 사람별 화면을 직원 분석의 직원 상세분석에 통합했다. 전체 비교/직원 상세분석으로 구분하고, 작은 요약 카드·시간/포스트/실제 상태 표·접힌 상세 통계를 사용한다. 중복 사람별 탭·모바일 직원별 요약·큰 표/자세한 메모 버튼은 제거했다.
- PC·모바일 주간/야간 미확정 후보에서 확정 버튼 옆 재생성을 지원한다. 기존 후보를 유지하고 새 후보를 선택하며 확정 전 실제 이력은 저장하지 않는다. 긴급 재생성은 기존 LOCK과 이탈 조건을 유지한다.
- 실제 이력은 프로젝트의 `history/`(야간), `history/day/`(주간)에 보관한다. `NIGHT_SHIFT_HISTORY_DIR` 설정 시 해당 경로를 사용한다. 삭제는 날짜 확인 후 휴지통으로 이동하며 덮어쓰기는 확인·백업 후 수행한다. PC와 모바일은 같은 서버의 데이터를 본다.


- 직원 분석의 입식·좌식은 순수 포스트만 집계한다. 순찰·차단봉은 별도 피로도로 표시하고 기존 실제 피로도 계산은 유지한다. 하층 순찰 1점, 상·중층 2점. 포스트 겸임 차단봉의 기존 예외 점수도 그대로 표시한다.
- PC 직원 상세분석은 가로 14시간표와 최장 실제 근무·휴게 굵은 구간 표시를 복원했다. 모바일은 시간/포스트/상태 3열 표와 작은 요약 카드를 유지한다.
- 주간 §28: 기존 8~11인 고정틀 유지. 그 밖의 신규·긴급 편성은 근근휴 필수, G2→G3·L1→L2 사이 비포스트 필수(순찰·교육 인정). G1→G2→G3→L1→L2→(C1)→(C2)→G1 순환은 하드 다음 강력 권장이다.
- 주간 일반 인원 편성이 INFEASIBLE일 때만 출근 A를 일반 인원으로 편입한다. 편입 이후 퐁당퐁당 통제는 없고 일반 규칙을 그대로 적용한다. 그래도 불가능하면 해 없음이다. UNKNOWN에는 자동 편입·해 없음 단정을 하지 않는다. 긴급 LOCK 과거는 보존하고 새 미래 단독 A/E 메움은 사용하지 않는다.

최신 검증: 직접 회귀검사 13개 통과. 전체 unittest 재검증 진행 중이며 최종 결과는 CHANGELOG에 기록한다. pytest 미설치 환경에서 unittest 전체 실행을 사용한다.
